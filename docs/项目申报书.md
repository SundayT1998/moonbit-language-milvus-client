## 项目简介

MoonBit Milvus Client 把 Milvus 官方 Go SDK 的核心能力移植到 MoonBit 生态，
为 RAG 应用、向量检索服务、语义搜索工具、推荐系统和可视化分析工具提供
可直接复用的向量数据库客户端。交付范围是**一条完整的读写链路**：集合与分区
管理、数据写入、索引装配、加载与刷盘、向量检索、标量查询，以及大结果集翻页。
项目面向需要在 MoonBit 里读写 Milvus 的库作者、工具开发者和应用开发者；
按依赖方向拆成 `entity` / `index` / `column` / `errors` / `transport` / `client`
六层，除 native 专属的连接实现外，其余在 wasm / wasm-gc / js / native 四个
后端下都编得过。

## 项目方向与通用性说明

- **通用基础库，不是某应用的附属模块。** 任何需要在 MoonBit 里读写向量数据的
  场景都能用，不绑定具体业务模型、框架或上层产品。
- **跨后端通用。** 模块 `preferred_target = "wasm"`，`client` / `entity` /
  `index` / `column` / `errors` / `transport` 四个后端一致通过；真连 socket 的
  `transport/native`、`client/native` 单独成包，用 `supported_targets` 声明。
- **传输可替换。** 发字节被抽成 `Unary = async (String, Bytes) -> Bytes` 这个
  函数值，上层编排逻辑因此可以脱离网络单测，也能接任意传输实现——
  gRPC、mock，或未来的自定义协议，不必改动调用逻辑。
- **协议对齐。** `.proto` 取自上游快照，字段编号、`DataType` 常量值
  （如 `FieldType = 101`）、Option 构造函数名与默认值均与上游逐条一致，
  能与官方服务端及其他语言 SDK 互通。
- **零外部数值依赖。** BF16 / FP16 转换手写位运算，逐位对齐 IEEE-754，不引运行时。
- **异步语义与上游一致。** `LoadTask` / `FlushTask` 的 `wait` 照搬上游 `Await`
  （先等一个间隔再查第一次，默认 200ms），调用方不必猜轮询时机。

## 预期使用场景

### 场景一：RAG 知识库的向量写入与语义检索

用 `entity` 声明集合 schema（`id` 主键 + `title` 标量字段 + 768 维
`FloatVector`），`Client::create_collection` 建集合，文档切块后的向量经
`Client::insert` 批量写入；`index` 包装配 HNSW + COSINE 索引后
`create_index`、`load_collection`，`LoadTask::wait` 等到就绪；提问时把问题向量化
送 `Client::search` 取最近邻，再按命中主键用 `Client::query` 拉回原文。
整条链路在 MoonBit 内闭环，不用切到别的语言进程。

### 场景二：大结果集的全量导出与批量分析

导出千万级集合做离线分析：`Client::query_iterator` 以 `batch_size=500` 逐批翻页，
客户端侧用主键游标 `pk > last` 往后挪，不吃服务端版本；每批经 `column` 包解成
列容器，按列类型（`get_as_int64` / `get_as_json_string` 等）读出落盘。
要按相似度做全量召回就换 `Client::search_iterator`（服务端侧 v2 游标），
翻到末尾自动发一次空检索收尾，不把服务端会话漏在那边。

### 场景三：多租户分区的数据隔离与按需加载

每个租户的数据写进独立分区（`Client::create_partition`）。低峰期只
`load_partitions` 加载热租户分区，`LoadTask::wait` 等进度到 100% 再对外服务；
用 `Client::get_load_state` 做健康探针，`Client::flush` 触发落盘并
`FlushTask::wait` 确认；流量回落后 `release_collection` 卸载释放内存。
分区的创建 / 删除 / 是否存在 / 列出全部由客户端封装，不用手拼 RPC。
（注意 `get_load_state` 对未见过状态返回 `Unknown(n)` 并保留原始序号，
不会被并进 `NotLoad` 而让调用方无限等下去。）

## 拟实现的核心功能

- 集合生命周期：创建 / 描述 / 是否存在 / 列出 / 删除，Option 名与默认值对齐上游；
  另提供 `simple_create_collection_option` 这类便利构造。
- 数据面：insert / upsert / delete；写入前本地校验列行数一致、向量维度吻合、
  空列直接拒——这些在服务端只表现为「静默少写」。
- 索引装配：`MetricType` / `IndexType` 枚举、HNSW / FLAT 等 builder，越界与
  非法组合在构造期报 `IndexParamError`，不等一次 RPC 往返。
- 加载与刷盘：`LoadCollection` / `ReleaseCollection` / `LoadPartitions` /
  `ReleasePartitions` / `GetLoadState`、`Flush` / `GetFlushState`，配可等待任务。
- 分区管理：创建 / 删除 / 是否存在 / 列出，含默认分区 `_default`。
- 检索与查询：`search` / `query`，`search_params` 固定写全七个键、顺序与上游一致。
- 大结果集翻页：`QueryIterator` 与 `SearchIterator`，末页与已关闭的状态可判定，
  不会重复发请求。
- 列容器：响应 `FieldData` → `Column`，覆盖全部标量 / 向量 / JSON 列；
  窄整数按位宽有符号收窄，两处有效性位图不一致时直接报错而非挑一边。
- 错误模型：`common.Status` → `MerError`，双轨错误码映射逐条搬上游，
  `is_retryable_err` 只看服务端下发的 `retriable`，加敏感信息脱敏。
- 传输层：配置、metadata 组装、gRPC status（跨 target）+ native 真连 socket。
- 验证：144 处 MoonBit 测试 + `moon check --target all` 四后端编译检查，
  外加连真 Milvus 容器（`milvusdb/milvus:v3.0.2`）跑的端到端集成自检
  `cmd/integration`（建集合 → 写入 → 建索引 → 加载 → 检索 → 查询 → 清理）。

## 移植或参考说明

- 原项目名称：Milvus Go SDK（`milvus-io/milvus` 仓库 `client/` 目录）
- 原项目链接：https://github.com/milvus-io/milvus
- 协议定义来源：https://github.com/milvus-io/milvus-proto
- 原项目许可证：Apache License 2.0（Copyright (c) LF AI & Data Foundation）
- 本项目许可证：Apache License 2.0（见仓库 `LICENSE`）
- 移植基线：`milvus-io/milvus` commit `1bcc8cb1`；`.proto` 快照的锚定 commit
  见 `proto/upstream/PROVENANCE.md`

与原项目相比，本项目做了以下简化和重新设计：

- 用 MoonBit 原生包结构组织代码，而非复刻 Go 的包与接口层级：上游一个
  `client/milvusclient` 包按依赖方向拆成 `entity` / `index` / `column` /
  `errors` / `transport` / `client` 六层。
- 只保留 column-based 一路 API，**不移植 row-based**；写入用 `WriteColumn`
  承接 `@column.ColumnValue`，让回读的 `Column` 改个名字就能写回去。
- 门面与连接分离：`client` 跨 target，`client/native` 才真连 socket。
- 收敛错误类型：`async fn` 只允许一个 `raise` 类型，故以单一 `ClientError`
  suberror（`Transport` / `Server` / `Schema` / `Encode` / `Decode`）取代上游的组合。
- 不缓存集合 schema（上游的 schema-mismatch 自动重试随之省略）：
  insert / upsert 的 `schema_timestamp` 留 0，schema 变更后由调用方重新描述集合。
- 迭代器两处刻意差异：`nq` 恒为 1（多给报 `Setup`）；`limit` 只决定「还发不发
  下一次请求」，**不跨批截断**（上游 `SearchIterator` 会切短）——见
  `client/iterator.mbt` 文件头的说明。
- BF16 / FP16 手写实现，对 float32 做 bit 截断加 round-half-to-even，
  逐位对齐 IEEE-754 binary16 与上游 `ml_dtypes.bfloat16`，零外部依赖。
- 归属合规：每个移植文件保留来源声明头（来源仓库 + 路径 + Apache-2.0 +
  Copyright），README 与仓库文档写明来源仓库、基线 commit 与改写定性；
  本项目是社区驱动的客户端，**不表述为** Milvus 官方 SDK。
